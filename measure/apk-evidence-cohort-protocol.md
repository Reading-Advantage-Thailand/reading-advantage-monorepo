# APK Evidence Cohort Protocol

Every corpus cohort depends on the accepted three-game pilot and inherits `apk-evidence-reconstruction-program.md`.

## Per-game required package

- Identity, route, implementation, copy, test, asset, and history reconciliation against the accepted denominator.
- Exact claim-evidence ledger.
- Complete real scene/state/transition model.
- Mechanic and learning blueprint.
- Developer-effort decomposition.
- Current responsive/browser audit under the program's mechanically reviewed runnable disposition and bounded historical responsive evidence otherwise.
- Concrete scene-level asset usages and variants.
- Conflicts, unknowns, and confidence.
- Role receipts, truth tests, and independent review report.

## Execution

- Maximum three games per batch.
- A phase task-ownership manifest assigns every task to explicit owner and reviewer roles. Each package has distinct evidence collector, requirements mapper, truth-test author, and reviewer; discovery, browser, history, and asset specialists are added when applicable.
- Complete and accept one batch before opening the next.
- No ontology or cross-game standardization decisions.
- One unsupported factual claim or denominator mismatch triggers the program stop-loss.
- Browser proof uses real input and state transitions, not screenshots alone.
- Every phase remediates all Critical, High, and Medium findings before checkpointing.

## Cohort completion

- Every assigned denominator item is covered exactly once.
- Every factual field and atomic proposition resolves to exact evidence. Only formatting, stable record IDs, and reviewer notes are non-factual exemptions.
- Every game accepted as runnable under the program definition has compact/wide browser evidence.
- Every unknown remains explicit and blocks dependent Must-have conclusions.
- A `fork_turns="none"`, tool-attested cohort reviewer reconciles every game, not a sample.
