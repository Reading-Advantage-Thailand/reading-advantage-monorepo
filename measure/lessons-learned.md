# Lessons Learned

> This file is curated working memory, not an append-only log. Keep it at or below **50 lines**.
> Remove or condense entries that are no longer relevant to near-term planning.

## Recurring Gotchas
- (2026-05-26, proxy_admin_guard_hardening) Next.js 16 promoted middleware (renamed to `proxy.ts`) to nodejs runtime as the default — `runtime` config in proxy files now THROWS. This removes the "edge-only" constraint that blocked many auth/DB-touching middleware designs. Before this, tech-debt notes assumed JWT redesign or `/api/verify` round-trips were required to do real session checks in middleware; now you can `import { requireRole } from "@reading-advantage/auth"` and call it directly. Always check the upstream framework constraint before designing around a "limitation" inherited from older docs. Vitest hoisted-mock pattern for proxy: `const { mock } = vi.hoisted(() => ({ mock: vi.fn() }))` then `vi.mock("@reading-advantage/auth", ...)` — referencing a top-level `const` inside a `vi.mock` factory triggers `ReferenceError: Cannot access X before initialization`.

## Patterns That Worked Well

- (2026-05-25, connection_pooling) Transaction-mode pooling (PgBouncer / Hyperdrive) needs THREE coordinated changes in postgres-js apps, not one: (1) `prepare: false` on the client (named statements are session-scoped and fail across pooler reassignments — `prepared statement "s_1" does not exist`); (2) split `DATABASE_URL` (pooled, app queries) from `DIRECT_DATABASE_URL` (session, migrations + seeds + `LISTEN/NOTIFY`) — `drizzle-kit migrate` takes an advisory lock that breaks under transaction mode; (3) for CLI scripts importing the shared `db`, build a dedicated direct client and guard the top-level entrypoint with `import.meta.url === pathToFileURL(process.argv[1]).href` (NOT a `\`file://${argv[1]}\`` template — fragile to spaces/unicode/Windows). The fallback pattern `process.env.DIRECT_DATABASE_URL ?? process.env.DATABASE_URL` with a single `console.warn` lets prod cut over incrementally without breaking deploys.

## Testing & Mocking

- (2026-05-02, review_remediation) Drizzle query-builder mocks must return **thenable objects**, not plain functions — `Object.assign(Promise.resolve(value), { limit: ..., innerJoin: ... })` for chain mocks. Cross-tenant authorization checks must be tested explicitly: `assertCan()` checks role only, not school/class ownership.

## Planning Improvements

- (2026-05-14, codecamp_advantage) Mock-DB unit tests can pass while real DB constraints are violated. Always verify schema alignment with a real database smoke test before considering schema tasks complete.
- (2026-05-14, codecamp_advantage) GitHub webhook handlers should normalize payload URLs before matching against stored repo URLs (trailing slashes, `.git` suffixes). URL mismatch caused silent webhook drops.
- (2026-05-14, codecamp_advantage) Streaming LLM responses via `streamText` with `toDataStreamResponse()` require careful client-side handling. The `useChatStream` hook must buffer partial chunks and only persist complete assistant messages to the DB.
- (2026-05-15, codecamp_review) API route handlers (Next.js `/api/`) bypass the tRPC/domain layer invariant — always route through domain functions with `assertCan()` and TenantDB, never import raw `db`. For admin data, use `adminProcedure` (not `protectedProcedure`) as defense-in-depth alongside client-side role checks.
- (2026-05-15, codecamp_review) Client-facing input schemas must never accept fields that could be used for privilege escalation (e.g., `role: "assistant"` on chat messages). Keep injection-prone fields as internal-only parameters in domain functions.
- (2026-05-15, codecamp_review) `reviewedAt` timestamps must be conditionally set: only stamp when the review status is terminal (not "pending"). Re-triggering a webhook sets status back to "pending", which should preserve the previous `reviewedAt`.
- (2026-05-22, prisma_drizzle_schema_unification) `drizzle-kit generate` requires a TTY for rename detection prompts; in non-TTY envs (Claude Code, CI) write migration SQL by hand and add the journal entry manually (snapshots can lag — fine for hand-written migrations). Always generate/write a migration in the same track as the schema change — schema-only constraints don't protect prod data until the migration runs.
- (2026-05-22, prisma_drizzle_schema_unification) Mock-DB's `from()` result needs `.limit()` and `.offset()` attached for domain queries that skip `.where()` (e.g., `listStories`). Added in `mock-db.ts` — update when writing no-filter list queries.
- (2026-05-22, prisma_drizzle_schema_unification) Cross-app collision rubric: tables with <30% column overlap, incompatible FK graphs, or different business domains should KEEP-SEPARATE with prefixed names (e.g., `science_classes`, `science_assignments`). Do not force unification just because names collide.
- (2026-05-23, prisma_drizzle_reading_controllers) Prisma `where: { schoolId }` on relation-less models failed silently. When migrating to Drizzle, route through a join on `users.schoolId`. Prisma migrations hold two SQL kinds: schema changes (replaced by Drizzle) and custom raw SQL (`MATERIALIZED VIEW`, `REFRESH` triggers) — grep and preserve the latter at `db-migrations/legacy-matviews/`.
- (2026-05-23, prisma_drizzle_reading_controllers) Raw-SQL strings inside controllers/services are invisible to TypeScript and to schema-rename tooling — they survive a Prisma→Drizzle migration with the OLD table/column names baked in (`"UserActivity"`, `"XPLogs"`, `a."createdAt"`, singular `article`). Audit every `db.execute(sql\`...\`)` and every raw-SQL helper at migration time, and add a per-SQL test that renders the query through `PgDialect.sqlToQuery` and greps for the unified names — type-check, lint, and build all pass without catching this.
- (2026-05-23, prisma_drizzle_reading_controllers) Manual `$n` interpolation into `sql.raw(...)` is unsafe and silently mishandles non-string parameter types (Date, json, boolean). Convert `$n`-based helpers to `sql.join([sql.raw(literal), sql\`${value}\`, ...])` so Drizzle/postgres-js binds every value through the driver. Throw on missing bind values; do not let them produce malformed SQL.
- (2026-05-23, prisma_drizzle_science_controllers) Prisma implicit M:N tables (`_LessonToStandard`, `_CurriculumUnitToLesson`, `_ClassToStudent`, `_QuizQuestionToStandard`) have NO Drizzle equivalent and are invisible to schema-audit tools that only look at top-level `model X { ... }` blocks. When porting a Prisma schema to Drizzle, grep for `Standard[]`/`Lesson[]`/`Class[]`-style array fields on both sides of every relation — each pair without an explicit through-table needs an explicit Drizzle junction with composite PK and matching `ON DELETE CASCADE` semantics. Discovered during Track 3 pilot; fixed by adding migration 0015 with 4 junctions.
- (2026-05-23, science_test_infra_drizzle) `prisma db push --force-reset` cannot share a database with applied Drizzle migrations — Prisma's `CREATE TYPE` has no `IF NOT EXISTS` path and aborts on enums Drizzle already created. When migrating an app off Prisma, the test-DB provisioning needs to swap to `drizzle-kit migrate` _early_ (not at the end), otherwise integration tests are unverifiable for the whole migration. Cleanest split: separate test DB on the same container (one `createdb`, zero compose changes), one-shot `globalSetup` for migration, per-test truncate-and-reseed for fixtures.
- (2026-05-24, prisma_drizzle_science_controllers) Client-bundle leaks are the dominant risk in a Prisma→Drizzle cutover and tsc/lint/manual route testing do NOT catch them — only `pnpm build` (Turbopack module resolution) does. `@reading-advantage/db` transitively imports `postgres` (node-only `fs`/`net`/`tls`/`perf_hooks`); any client component reaching a "shared lib" that touches `db` drags the whole driver into the browser bundle. Fix pattern: split `<mod>.ts` → `<mod>.constants.ts` (pure data/types/fns) + `<mod>.ts` server-only shim opened by `import "server-only"` (NOT `"use server"` — `server-only` fails at build the moment a client component imports). Re-export constants from the shim for back-compat. See [04d8fa5] badges, [d596dfb] xp. Always run `pnpm build` after a large port.
- (2026-05-24, prisma_drizzle_science_controllers) Prisma-removal greps have blind spots. `from '@/lib/prisma'` misses `vi.mock('@/lib/prisma', ...)` and dynamic `await import('@/lib/prisma')` ([ba5be9f]); local `interface PrismaSession` + DI param `prisma` matches `prisma.<call>` grep but is NOT Prisma — triage, then rename for clarity ([06a4117]). Always grep the raw substring (`@prisma`, `/lib/prisma`) in addition to import-path patterns; then audit `vi.mock`/`await import` separately.
- (2026-05-24, prisma_drizzle_science_controllers) postgres-js error shape ≠ Prisma: P2002 → `23505`, P2034 → `40001`, original on `.cause`; `decimal(p,s)` returns as string (write via `String(x)`, compare via ``lt(col, sql`0.6`)``). Wrap explicitly at the call site when callers use exception-based control flow — silently changing thrown shapes breaks routes without a type error.
- (2026-05-24, prisma_drizzle_science_controllers) Drizzle vs Prisma session lifecycle gotchas: `createSession()` returns `{ token, ... }` — cookie mocks must use `session.token`, not `session.id`; `requireAuth`/`requireRole` raise `NEXT_REDIRECT` (caught as 500, not 401) — assert non-2xx, not exact status; `env.DEV_AUTH_ENABLED` is evaluated at IMPORT time, so mock `@/lib/env`, not `process.env`.
- (2026-05-24, prisma_drizzle_science_controllers) drizzle-zod loses per-column constraints that Prisma carried (length/range) and emits too-loose schemas; hand-write the Zod from the spec when constraints matter ([20bd954]).
- (2026-05-24, prisma_drizzle_science_controllers) Move-don't-copy migration discipline: one file per commit, behavior-preserving, with `git rm` of the old path in the SAME commit (cleaner reverts, easier review). Backfill pagination needs `(completedAt, id)` composite ordering for stable resumability, not opaque id cursors.
- (2026-05-24, prisma_drizzle_science_controllers) Re-evaluating a tech-debt entry whose original blocker is resolved is itself high-value bookkeeping: the `ignoreBuildErrors` flip ([fdd3298]) failed not because of Prisma but because of 354 testing-library matcher-narrowing errors and 4 next@16 dup-types — the Prisma-removal track surfaced the *real* build blockers and updated the debt entry. Always re-check assumptions in tech-debt notes when closing a track that touches them.
- (2026-05-27, www_i18n_l10n_remediation) i18n remediation: batch parallelism (extract keys → update pages). `npm run i18n:audit` is the single source of truth.
- (2026-06-03, protocol_v1_1_graphdb_20260603) Always pre-flight `build-graph stats` before an audit; 0 files means the audit will silently degrade to grep-only. Full monorepo `build-graph scan` times out on large repos (>5 min) — scan `packages/` first, then incrementally `update` with app files. graph.db should be gitignored and rebuilt in CI, not committed.
- (2026-06-04, app_domain_migration) Domain package `dist/` files must be rebuilt after refactoring source imports. Subagent parallelism works well for route migrations: each route is independent, and the pattern (extract business logic → thin route → update tests) is mechanical once established.
- (2026-06-04, tenant_db_school_id) Tenant predicate coverage is a test, not a guideline — `tenant-coverage.test.ts` scans every domain file for `createTenantDB` usage and fails the build if a file has DB access but no tenant guard. `Tenant.schoolId` is `string | null` — insert calls need `tenant.schoolId!` (non-null assertion after `assertCan` verifies access). Science content tables (lessons, standards) without natural school context get a default school during backfill; orphan rows with NULL FK chains also get assigned to the default school.
- (2026-06-04, argon2id_password) `@node-rs/argon2` does NOT natively verify bcrypt hashes — must keep `bcryptjs` as verify-only dependency for cross-algorithm support. The `isolatedModules` TS flag blocks `const enum` access from native modules — use numeric literal `2` for `Algorithm.Argon2id`. Auth adapter flatten: Next.js cookie-based wrappers (getCurrentSession, requireAuth, requireRole) must remain local because they depend on `next/headers`; the shared auth package is framework-agnostic. Re-export shared types to eliminate local type drift.
- (2026-06-04, audit_log_infrastructure) Append-only at the DB level (`REVOKE UPDATE, DELETE`) is the right enforcement — the application code can be audited, but a permission error from the DB is a hard guarantee. Fire-and-forget audit logging (`.catch(() => {})`) prevents audit failures from blocking primary actions. Domain functions that import `db` directly (vs taking `TenantDB` as a param) cannot be unit-tested with mock-db — need either refactoring to accept `db` as a parameter, or integration tests with a real database. Tenant-coverage test needs an exemption list for global tables (like `audit_events`) that intentionally skip tenant scoping.
- (2026-06-05, ai_adapter_package) Mock provider with deterministic responses is the right unit-test pattern for AI adapters; real providers are integration-tested only with API keys present. When an app's vitest config doesn't include workspace packages in `resolve.alias`, adding the package to `package.json` dependencies creates the pnpm symlink and fixes resolution — no vitest config change needed. Model IDs with provider prefixes (e.g., `google/gemini-3-pro-image`) must be stripped before passing to the AIClient since the provider is already selected by the client instance.
- (2026-06-10, storage_package_20260603) Domain functions must not carry transport concerns (fetch, headers, revalidation) — move them to the caller. The `next: { revalidate: 300 }` cast in `getPracticeIssues` tied domain code to Next.js's extended `RequestInit`; extracting to a `GitHubClient` adapter made the function portable to workers/CLI. `pnpm --filter <pkg> test` works for new workspace packages, but `npx vitest run` directly in the package dir may hang (vitest 4.x + ESM) — always invoke through pnpm. ESM packages with `"type": "module"` require `.js` extensions in relative imports; TypeScript resolves them to `.ts` at compile time but Node.js ESM loader needs them at runtime.
- (2026-06-06, audit_log_retention_dsar_20260605) Advisory-lock job pattern: consolidate `pg_try_advisory_lock`, work, and `pg_advisory_unlock` onto a single session. Privileged-connection DELETE on append-only tables requires `DIRECT_DATABASE_URL`.

## CI & Build
- (2026-06-07, ci_typecheck_alignment_20260603) `ignoreBuildErrors: true` is the single biggest type-safety hole in a Next.js monorepo — ~370 tsc errors masked 6 root causes (testing-library matcher narrowing, INTERN role widening, missing test siblings, ProcessEnv narrowing, next@16 duplicate instances, misc), each fixable in a small PR. Removing it required a 14-phase track. Always wire `check-types` into CI before flipping the flag; never ship `ignoreBuildErrors: true` to main. Red-phase commits must contain ONLY the test file + Measure doc edits — on dirty trees, `git add` stages pre-existing modifications too; check `git status --short` before committing. Recurring SHA-drift: recording a phase's commit SHA in plan.md *before* the commit is rebased/squashed onto the default branch leaves a dangling reference (object survives until `git gc`, then `bad object`) — codecamp Phase 8 cited orphan `31496a8` for work that landed as `3fb1a87`, the 6th such fix. Capture the SHA only from the commit that is an ancestor of HEAD (`git merge-base --is-ancestor <sha> HEAD`), and prefer recording it in a follow-up doc commit after the code commit is on-branch.
