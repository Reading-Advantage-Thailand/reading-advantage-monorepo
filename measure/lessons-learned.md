# Lessons Learned

## Recurring Gotchas
- (2026-06-23, primary_advantage_drizzle_migration_20260526) **FR-2 grep gate must include runtime call shapes, not only import literals.** The Phase 9 FR-2 audit used `grep -rE '(@prisma/client|@/lib/prisma|@prisma/adapter-pg|\"prisma\")'` which matched zero in source — yet two real Prisma-shape *calls* remained (`db.assignment.findUnique(...)` and `db.$transaction(async (tx) => { tx.article.create(...); ... })`). The phase-level audits only matched import literals, not the runtime call shapes. For future framework-migration tracks, the FR-X audit should always include both: (a) import literals AND (b) the legacy-framework's runtime call shape (e.g., `<client>.<table>.<method>(...)` and `<tx>.<table>.<method>(...)`). The final-acceptance audit caught these 2 sites; both are fixed in commit `5273558d`.
- (2026-06-13, db_migration_ledger_20260611) Drizzle migrator uses strict-< on `when` stamps: it skips any migration whose `when` ≤ the last applied ledger row. Non-monotonic `when` values in `_journal.json` (from hand-edits or older tooling) silently cause migrations to be skipped on existing databases while fresh DBs apply everything — hiding the bug in dev/CI. The production-ledger ceiling `1779120000000` was chosen to separate the re-stamped era (0–16 ≤ ceiling, 17+ > ceiling). Always validate `when` monotonicity in `journal-integrity.test.ts` after hand-editing the journal.
- (2026-06-06, audit_log_retention_dsar_20260605) Append-only audit logs are enforced at the DB level with `REVOKE UPDATE, DELETE` on the `audit_log` table; the retention job must use a privileged connection (`DIRECT_DATABASE_URL` session-mode client) to perform the periodic DELETE, because the pooled `DATABASE_URL` transaction-mode client cannot. The retention job also takes a `pg_try_advisory_lock` keyed on a constant (e.g., `hashtext('audit_retention_job')`) so concurrent invocations across replicas no-op without blocking — always pair the lock with `pg_advisory_unlock` in a `finally` block to avoid the lock leaking across the connection pool. Closeout: the `phase-7-closeout.test.ts` file in `packages/auth/src/__tests__/` asserts the track's tech-debt row + lessons-learned entry exist before the track is fully archived; missing either trips the test for every package's `test` task in the aggregate gate.
- (2026-05-26, proxy_admin_guard_hardening) Next.js 16 promoted middleware (renamed to `proxy.ts`) to nodejs runtime as the default — `runtime` config in proxy files now THROWS. This removes the "edge-only" constraint that blocked many auth/DB-touching middleware designs. Before this, tech-debt notes assumed JWT redesign or `/api/verify` round-trips were required to do real session checks in middleware; now you can `import { requireRole } from "@reading-advantage/auth"` and call it directly. Always check the upstream framework constraint before designing around a "limitation" inherited from older docs. Vitest hoisted-mock pattern for proxy: `const { mock } = vi.hoisted(() => ({ mock: vi.fn() }))` then `vi.mock("@reading-advantage/auth", ...)` — referencing a top-level `const` inside a `vi.mock` factory triggers `ReferenceError: Cannot access X before initialization`.

## Patterns That Worked Well

- (2026-05-25, connection_pooling) Transaction-mode pooling (PgBouncer / Hyperdrive) needs THREE coordinated changes in postgres-js apps, not one: (1) `prepare: false` on the client (named statements are session-scoped and fail across pooler reassignments — `prepared statement "s_1" does not exist`); (2) split `DATABASE_URL` (pooled, app queries) from `DIRECT_DATABASE_URL` (session, migrations + seeds + `LISTEN/NOTIFY`) — `drizzle-kit migrate` takes an advisory lock that breaks under transaction mode; (3) for CLI scripts importing the shared `db`, build a dedicated direct client and guard the top-level entrypoint with `import.meta.url === pathToFileURL(process.argv[1]).href` (NOT a `\`file://${argv[1]}\`` template — fragile to spaces/unicode/Windows). The fallback pattern `process.env.DIRECT_DATABASE_URL ?? process.env.DATABASE_URL` with a single `console.warn` lets prod cut over incrementally without breaking deploys.

## Testing & Mocking

- (2026-05-02, review_remediation) Drizzle query-builder mocks must return **thenable objects**, not plain functions — `Object.assign(Promise.resolve(value), { limit: ..., innerJoin: ... })` for chain mocks. Cross-tenant authorization checks must be tested explicitly: `assertCan()` checks role only, not school/class ownership.

## Planning Improvements

- (2026-05-14, codecamp_advantage) Mock-DB unit tests can pass while real DB constraints are violated. Always verify schema alignment with a real database smoke test before considering schema tasks complete. GitHub webhook handlers should normalize payload URLs before matching against stored repo URLs (trailing slashes, `.git` suffixes).
- (2026-05-15, codecamp_review) API route handlers must route through domain functions with `assertCan()` and TenantDB. `reviewedAt` timestamps must be conditionally set: only stamp when the review status is terminal (not "pending"). Re-triggering a webhook sets status back to "pending", which should preserve the previous `reviewedAt`.
- (2026-05-24, prisma_drizzle_program Tracks 1–3) **Prisma→Drizzle migration gotchas:** (a) `@reading-advantage/db` transitively imports `postgres` (node-only) — only `pnpm build` catches client-bundle leaks; fix: split `<mod>.ts` → `<mod>.constants.ts` + `<mod>.ts` server-only shim with `import "server-only"`. (b) Raw-SQL strings inside controllers are invisible to TypeScript and schema-rename tooling — they survive migration with OLD table/column names baked in; audit every `db.execute(sql\`...\`)`. (c) `drizzle-kit generate` needs a TTY for rename detection prompts; in non-TTY envs write migration SQL by hand. (d) postgres-js error shape ≠ Prisma: P2002 → `23505`, P2034 → `40001`. (e) Move-don't-copy: one file per commit, behavior-preserving, `git rm` of old path in same commit. (f) drizzle-zod loses per-column constraints that Prisma carried — hand-write Zod from spec when constraints matter. (g) Re-evaluating a tech-debt entry whose original blocker is resolved is itself high-value bookkeeping.
- (2026-06-04, app_domain_migration) Domain package `dist/` files must be rebuilt after refactoring source imports. Subagent parallelism works well for route migrations.
- (2026-06-04, tenant_db_school_id) Tenant predicate coverage is a test, not a guideline — `tenant-coverage.test.ts` scans every domain file for `createTenantDB` usage. `Tenant.schoolId` is `string | null` — insert calls need `tenant.schoolId!` after `assertCan` verifies access.
- (2026-06-04, argon2id_password) `@node-rs/argon2` does NOT natively verify bcrypt hashes — keep `bcryptjs` as verify-only dependency. Auth adapter flatten: Next.js cookie-based wrappers must remain local because they depend on `next/headers`.
- (2026-06-04, audit_log_infrastructure) Append-only at the DB level (`REVOKE UPDATE, DELETE`) is the right enforcement. Fire-and-forget audit logging (`.catch(() => {})`) prevents audit failures from blocking primary actions.
- (2026-06-05, ai_adapter_package) Mock provider with deterministic responses is the right unit-test pattern for AI adapters; real providers are integration-tested only with API keys present. Model IDs with provider prefixes must be stripped before passing to the AIClient since the provider is already selected by the client instance.
- (2026-06-18, housekeeping_batch_20260603) **Git notes backfill:** `git notes add -m "..."` fails when a note already exists (`-f` forces replace, `git notes append -m "..."` preserves content). Prefer append to avoid losing rich task-audit content. Notes live under `refs/notes/commits` and must be pushed explicitly (`git push origin refs/notes/commits`). Track-ID-in-note is a lightweight cross-reference that survives rebase better than body-footers when notes are attached post-facto. When backfilling, use explicit SHA lists rather than heuristic filters (body-content regex captured only 22/52 members).
- (2026-06-19, housekeeping_batch_20260603) **Batched housekeeping is the right pattern for Low/Medium audit findings.** Grouping 10 small, isolated fixes into a single track (`housekeeping_batch_20260603`) with one PR is cheaper to review than 10 separate PRs. Each fix ships in its own commit for easy review and cherry-pick. The pattern works best when findings are non-critical and independent — batch them, resolve them in one pass, and archive. Deferred items (F-1306 → Track 11) are documented in the plan rather than holding the batch open.
- (2026-06-12, codecamp_review_ai_consolidation_20260605) Adapter-factory DI-seam pattern: keep the narrower `(system, prompt) => Promise<ReviewResult>` callback shape on `reviewExercise` and add a thin `aiClientToGenerateReview` adapter at the call site — lower blast radius than widening the domain function's DI to accept the full `AIClient` interface. OpenRouter-as-OpenAI-variant: provider is a thin `baseURL` swap over the OpenAI SDK; no new provider boilerplate needed. Credential-gated preflight (`it.skipIf(!process.env.OPENROUTER_API_KEY)`) is the reusable pattern for capability gates that must not block CI without a real key.
- (2026-06-21, observability_stack_20260603) AsyncLocalStorage + Sentry + OTel is the right observability stack: a single `RequestContext` ALS store auto-attaches `requestId`/`userId`/`latencyMs` to every log line emitted from inside a route handler, Sentry's Next.js `withSentryConfig` + `instrumentation.ts` covers live-path init + error capture + OTel span recording with zero per-route wiring, and a real OTel `tracer.startActiveSpan('ai.generateObject', ...)` over the `InMemorySpanExporter` test fixture exercises the live SDK end-to-end (not a fake harness). The alternative (pino + Datadog + per-app exporters) is more work for less value: it duplicates the request-context plumbing pino already gives you, requires a custom transport for the Datadog side, and forces every app to wire its own exporter registration — none of which Sentry's `withSentryConfig` + the Next.js `instrumentation.ts` convention require. Pin the live-path test boundary at `next.config.ts` (Sentry) + the app-root `instrumentation.ts` (OTel) so a regression in either wrapper fails the closeout gate, not a per-route test.

## CI & Build
- (2026-06-07, ci_typecheck_alignment_20260603) `ignoreBuildErrors: true` is the single biggest type-safety hole in a Next.js monorepo — ~370 tsc errors masked 6 root causes (testing-library matcher narrowing, INTERN role widening, missing test siblings, ProcessEnv narrowing, next@16 duplicate instances, misc), each fixable in a small PR. Removing it required a 14-phase track. Always wire `check-types` into CI before flipping the flag; never ship `ignoreBuildErrors: true` to main. Red-phase commits must contain ONLY the test file + Measure doc edits — on dirty trees, `git add` stages pre-existing modifications too; check `git status --short` before committing. Recurring SHA-drift: recording a phase's commit SHA in plan.md *before* the commit is rebased/squashed onto the default branch leaves a dangling reference (object survives until `git gc`, then `bad object`) — codecamp Phase 8 cited orphan `31496a8` for work that landed as `3fb1a87`, the 6th such fix. Capture the SHA only from the commit that is an ancestor of HEAD (`git merge-base --is-ancestor <sha> HEAD`), and prefer recording it in a follow-up doc commit after the code commit is on-branch.
- (2026-06-10, codecamp_perf_warm_dashboard acceptance) Top-level `npm run build` is the supervisor gate, so app-isolated build breaks block every track's acceptance. Two recurring root causes after the argon2id migration (e0bd0a82): (1) Apps with `middleware.ts` (Edge runtime) that transitively import `@reading-advantage/auth` fail with "Module not found: Can't resolve '@node-rs/argon2-wasm32-wasi'" — the fix is rename → `proxy.ts` (Next.js 16 default nodejs runtime, per the proxy_admin_guard_hardening lesson). (2) Apps that import auth only from App Routes / Server Components fail with "Package @node-rs/argon2 can't be external — install it into the project directory" — Next.js Turbopack's `serverExternalPackages` mechanism requires the native package to be declared in the app's own `package.json`, not just transitively. Both are mechanical fixes; check both whenever rolling out a native-binary auth dep across apps.
- (2026-06-11, codecamp_qa_prod_20260517 closeout) `gate_closeout` in `measure/automation-supervisor.py:1015` checks `active_registry_contains_track`, which splits `measure/tracks.md` on the literal string `## Archived Tracks` and considers everything before it the "active section". If the file has no `## Archived Tracks` H2 header, the entire file is "active" and any occurrence of the track_id (even an `[x]` entry with a `./archive/<id>/` link) trips the gate. Three failed closeout attempts before the supervisor's regex was traced. Fix: every closeout must ensure `## Archived Tracks` exists as an H2 header AND the closing track entry sits after it. Existing already-archived `[x]` entries above the header are not the supervisor's concern, only the current track_id. Do not bother migrating older entries into the section unless explicitly asked.
- (2026-06-12, post_24h_audit_remediation) Source-text regex tests (`env-guards.test.ts`) prove the source *looks* correct, not that it behaves correctly. Always prefer behavior tests that import and exercise the module. Stale domain `dist/` causes "Failed to resolve entry" errors in downstream tests — rebuild packages after moving exports between subpaths. `tsc --noEmit` (check-types) fails when tests import from outside `rootDir` even if the import target is a `.js` artifact — use `tsconfig.build.json` for the build and accept the check-types limitation for tests that reach outside src/.
- (2026-06-24, review_findings_remediation_20260624) **Never bend production code to satisfy a test's structural string assertion.** A previous track (`post_24h_audit_remediation_20260612`) shipped a `reset-password` test that asserted a literal `bcryptjs` reference in the source — the test was rewritten away (commit `019b9d83`) when the production code was switched to `@node-rs/argon2` because the source-string assertion would have failed the move. Structural assertions (`existsSync(file)`, `src.toMatch(/export default function/)`, CSS-literal regex) and module-mock passthroughs (`transaction: vi.fn((fn) => fn(mockDb))`) are a "test gaming" smell: they prove the source LOOKS right or that mocks cooperate with the code, not that the system behaves right. The right test: hit the real handler (route-level) or thread a spy that records which handle each op was called on (race-safety) — both surfaces can be added at low cost and remain meaningful through refactors. The 72h review of 4 closed tracks (primary-drizzle, sales-mvp, video-pipeline, post-24h) caught this pattern across 8 sites; FR-9/FR-10/FR-12 in this track retire it.

## Wave 2 — False-Green Prevention Patterns (2026-07-03, wave2_confidence_restoration_20260628)
- **Counterexample fixtures are mandatory for source-scan guards.** A guard that scans production code for a forbidden pattern (direct SDK import, missing sentinel, missing consent, stale docblock) and asserts `hit count === 0` passes vacuously on an empty codebase. Every source-scan guard must ship with a counterexample fixture (a file that DOES contain the banned pattern) and assert it IS detected — without it the guard silently rotting into "scans 0 files" is undetectable. Used by Wave 2: `wave2-provider-architecture-guard.test.ts`, `wave2-ai-barrel-no-raw-sdk.test.ts`, `wave2-test-signal-inventory.test.ts`, `wave2-live-smoke-opt-in.test.ts`, `wave2-test-truthfulness.test.ts`.
- **Ratchet, don't zero, for large deferred sweeps.** The 621-call-site `console.error → structured-logger` migration is too large for a single track; Wave 2 installed a ratchet pinned at the current baseline (`CONSOLE_ERROR_BASELINE = 621`) so any new `console.error` FAILS the guard, but the existing 621 don't need to be fixed in Wave 2. Wave 6 lowers the baseline as it migrates call sites. The discipline: ratchet regressions closed; deferred cleanup recorded with a named owner wave; NEVER delete the test to make the suite green. A `[b] deferred:<owner>` row in the plan keeps the deferred scope visible to the supervisor.
- **Opt-in gating for live-prod smoke tests.** CodeCamp's 14 `phase-*` prod-smoke files defaulted to `https://codecamp.reading-advantage.com` without an opt-in flag. Phase 3 quarantined them behind `RUN_LIVE_SMOKE=true` + a per-phase env var (`PHASE{N}_PROD_URL`); no `?? "https://prod..."` fallback. Local CI and CI-without-credentials now skip these safely. Default-to-prod is a false-green pattern: a test that silently hits production is indistinguishable from one that hit a mock — and a green CI that exercises production by accident is worse than a red one.
- **Barrel quarantine > barrel rewrite for adapter adoption.** `packages/ai/src/index.ts` originally re-exported 7 raw vendor SDK symbols (`createOpenAI`, `generateText`, etc.) — a Wave 2-specific leak. Phase 2 removed the barrel re-exports and moved the raw symbols to `packages/ai/src/internal-sdk.ts` with a named allowlist entry in the production architecture guard. Production code can no longer import the raw SDKs through the barrel; the `internal-sdk` quarantine lets `__tests__/` and migration helpers still reference them under a documented reason. A full rewrite (every consumer reworked to use the AIClient) is Wave 6; the quarantine plus the architecture guard delivers the no-regression value today.
- **Acceptance-caught pre-existing-vs-regression discipline (fresh-DB migrate probe).** Wave 2 ran all 4 phase guard chains at HEAD before closeout and labeled every aggregate failure with an owner (`ai_sdk_major_migration` for 19 ai artifact tests; `db-platform` for the 2-test `env-guards` full-suite timeout flake; `codecamp_qa_prod_20260517` for prod-smoke Phase 8.5/12/13; `wave5_public_surface_completion_20260628` for www next-intl; sales type-config for `lib/trpc.ts:4` TS2742; sandbox infra for science DB-globalSetup). The discipline: aggregate red is allowed at closeout only when 100% of failures are pre-existing-with-named-owner AND no Wave 2 change introduces a new one. Re-running the 4 phase guard chains after every Wave 2 commit catches regressions in ~30 seconds. Never claim "aggregate green" while the aggregate is red — A5 violation; state the honest picture with labeled counts and a named owner per failure.
