## 3. Code quality observations

- **Casing normalized, vocabulary not.** `roleEnum` = `INTERN, STUDENT, TEACHER, ADMIN, SYSTEM, SALES_REP, SALES_ADMIN`; the proxy tables use `user, student, teacher, admin, system`. So: `INTERN`/`SALES_REP`/`SALES_ADMIN` match no `protectedRoutes` entry → `/unauthorized` on `/settings`, and `SALES_ADMIN` (hierarchy 3, same as `ADMIN`) is blocked from `/admin`; none have a `roleDefaultRedirects` entry → post-login fallback to `/`; and `"user"` maps to no DB enum value at all (dead NextAuth-era entry).
- **Fix applied at the wrong altitude.** `packages/auth` already exports canonical `ROLES`, `Role`, `ROLE_HIERARCHY`, `ROLE_ROUTES`, `roleAtLeast`. Keying `protectedRoutes` off `Role` would remove both casts and both `.toLowerCase()` calls, and turn the missing roles into a type error instead of a silent 403.
- **`(token.role as string)` discards typing.** `currentUser()` already returns a typed role; combined with `typescript: { ignoreBuildErrors: true }` in `next.config.ts`, nothing would catch a regression. It also introduces a new failure mode: a null role now throws a `TypeError` inside the proxy (500 on every matched route) rather than falling through. Low likelihood (`role` is `notNull`), but new.
- **The same defect survives outside the proxy**, untouched: `components/shared/app-layout.tsx:47` and `components/nav/user-account-nav.tsx:106-122` compare `user.role === Role.student` against the *lowercase* `types/enum.ts` enum — always false for real uppercase roles (students lose the leaderboard, admins lose nav entries).
- Spec and plan are two sentences with no acceptance criteria; `deviation_notes` does correctly flag this as a recovery track.
