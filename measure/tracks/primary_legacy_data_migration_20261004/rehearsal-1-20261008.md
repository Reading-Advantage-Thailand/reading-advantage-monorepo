## Defects found and fixed

1. **Times moved 8 hours early.** postgres.js read the legacy `timestamp(3)` columns in the process
   time zone (this machine: UTC+8), so every moved time (XP, reading logs, card due dates, license
   expiry, class code expiry) was 8 hours early. Found by the new student sample check. Fix: the
   legacy connection reads `timestamp` as UTC (`LEGACY_UTC_TIMESTAMP`, integration 7bb6b1065).
   `primary_etl_20261007` keeps the shifted times; rehearsal 1 replaces it.
2. **Question order arbitrary.** The questions of an article share one `createdAt`; the ETL numbered
   them by `ctid`. Workbooks' verify found 11 packages with a different order (59 MCQ, 2 SAQ rows).
   Fix: order by `createdAt`, then the cuid id (`QUESTION_ORDER_SQL`, 7bb6b1065).

Not a defect: locally, `pnpm --filter @reading-advantage/db doctor --check` runs the built-in
`pnpm doctor`, because `~/.local/bin/pnpm` is a shim for `npx -y pnpm`. Cloud Build uses corepack
pnpm 11.8.0, and its `doctor-check` passed (2026-09-24). Locally, use `pnpm ... run doctor`.

## Student home sign-in (owner decision 2026-10-08)

A class code works only while the teacher has the class open (3 hours at most), and a QR card also
needs an open class. Away from the classroom a student signs in only with a username and password.
Migrated students have no password, so none of them can sign in at home after the cutover until the
teacher makes the class sheet. The legacy class code worked at all times. Decision (option A): each
teacher makes and prints the class sheet at the cutover (spec runbook step 10). Student usernames (owner decision 2026-10-08): the legacy emails (643 of 643, for example the pattern
`name.123@gmail.com`) only existed because the old system required one, and an email username
suggests email support. A class-based name (`p3a12`) breaks when the student moves up a grade. So the
ETL and the app give each student a permanent username of two words and two digits
(`bluetiger47`); spec D6.
The browser check `.qa-tmp/rehearsal1-gonogo.mjs` now ends the class, makes the class sheet, and
signs a student in with the sheet username and password (spec checklist login 5).

- The agent may not read database passwords, so the owner runs
  `~/Desktop/primary-cutover-inputs/rehearsal1-cloud.sh` (private folder): the secret
  `PRIMARY_V2_DATABASE_URL` (the legacy URL with database `primary_v2`; only the `host` parameter

  doctor, the ETL from the live legacy database (read only), temporary passwords, and the three checks.
- Cloud Build: the root `.gcloudignore` leaves out `apps/primary-advantage`, so a submit from the
  repository root cannot build Primary. Use a reduced context (`git archive HEAD` of the root files,
  `apps/primary-advantage`, and `packages`; 696 MB, mostly `packages/advantage-play-kit`), as in
  `docs/deployment/gcp-cloud-run-monorepo-deployment.md` §9. The rehearsal config adds `--no-traffic`
  and `--tag=rehearsal1` to the deploy step (runbook step 6: the first deploy takes no traffic).
- `primary_v2` is a rehearsal target: drop and recreate it before rehearsal 2 and the cutover (the
  ETL upserts and never deletes).
- Run 1 (2026-10-08 09:35 UTC): the secret, the proxy, and the guard passed. Migrate failed after
  5 minutes with `must be able to SET ROLE "durable_job_audit_owner"` (Cloud SQL log). On Cloud SQL
  `postgres` is not a superuser, and migrations 0052 and 0054 need the migration user to act as that
  role. Migrate runs in one transaction, so `primary_v2` stayed empty. The script filter also hid the
  error text. Fix in the script: a role step before migrate (create the two roles if missing, then
  `GRANT durable_job_audit_owner TO CURRENT_USER WITH INHERIT FALSE, SET TRUE`), and each step now
  writes its full output to a file and shows the last lines when it fails. Local proof on a scratch
  database with a non-superuser owner: migrate failed with the same error, then the role step,
  migrate, and doctor passed. Spec 1.7 §8 step 2 records the rule.
