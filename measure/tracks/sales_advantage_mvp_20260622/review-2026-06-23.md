## Code quality observations

- **Strengths:**
  - Contract-first TDD is visible: Red tests were added before implementation for the AI adapter and domain layer.
  - Domain layer is well-structured (schema/contracts/queries/mutations/permissions/errors/index) and mirrors the codecamp pattern.
  - Roleplay evaluator clearly documents the primary single-pass multimodal path and the two-pass fallback.
  - New `SALES_REP` / `SALES_ADMIN` roles are registered and used.

- **Concerns:**
  - `apps/sales-advantage/app/api/roleplay-attempts/route.ts` catches storage errors and comments that storage is "non-critical for the eval flow" — this contradicts the spec requirement that audio is stored privately and evaluation is tied to the stored artifact.
  - The route uses `db as never` and a convoluted `wrappedEvaluate` closure with nested type casts; this needs cleanup.
  - `packages/api/src/routers/sales.ts` uses string role comparisons (`ctx.auth.user.role !== "SALES_REP"`) instead of the typed permission assertions defined in `packages/domain/src/sales/permissions.ts` and registered in `packages/auth`.
  - The storage key is generated from `Date.now()` rather than the attempt id created by the domain function, making later correlation fragile.

## Risks or blockers

1. **Silent storage failures** could leave evaluations without retrievable recordings, violating the acceptance criteria and retention assumptions.
2. **Upload-route type safety** is weak (`as never`, `as unknown`) and may fail `check-types` or runtime edge cases.
3. **No full-app build evidence** yet for `sales-advantage`; Next.js 16 + Tailwind v4 + next-intl integration may surface build issues.
4. **Real OpenRouter multimodal evaluation** has not been exercised end-to-end; the free-tier model availability/rate-limit risk from the spec risk register remains open.
5. **pnpm 11 optional-native-binary fetch warnings** (`EPIPE` against `registry.npmjs.org`) prevent clean `pnpm install` in this environment, so broader monorepo gates are currently environment-blocked.

## Recommended next actions

1. Harden `app/api/roleplay-attempts/route.ts`: propagate storage failures (or return a clear error), use the returned `attempt.id` as the storage key, remove `as never`/`as unknown` casts, and simplify the evaluator closure.
2. Refactor `salesRouter` to use typed `assertCan` / permission assertions instead of raw string role checks.
3. Run `pnpm turbo run lint test check-types build --filter=sales-advantage` once the pnpm environment is stable; fix any build/type issues.
4. Perform manual end-to-end QA with a real audio recording against OpenRouter to validate the single-pass multimodal path and fallback.
5. Complete remaining Phase 5–8 tasks (full UI polish, curriculum approval workflow, Docker/cloudbuild, deploy smoke test).
