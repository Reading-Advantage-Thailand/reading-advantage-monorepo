# API authorization audit, 2026-10-12

Source: read-only audit by the orchestrator. Cluster 1 is fixed in this track (task "School and admin
authorization fixes from the API audit"). Cluster 2 goes to another helper.

Role rule: `users.role` is the truth on migrated data. `user_roles` has 0 rows. The new helper
`apps/primary-advantage/server/utils/school-access.ts` (`canManageSchool`) allows the school owner,
an ADMIN of the same school (`users.role` and `users.school_id`), and SYSTEM.

## Cluster 1 (fixed here)

1. Critical. `app/api/users/me/school/route.ts` POST: a school-less STUDENT could create a school and
   become ADMIN. Now only a TEACHER or ADMIN without a school, or SYSTEM, may create. A STUDENT gets 403.
   A TEACHER becomes ADMIN. ADMIN and SYSTEM keep their role.
2. High. Same file PATCH: any member could rename the school and change the contact. Now PATCH needs
   `canManageSchool`. GET and the school profile page blank the admin and owner emails for a STUDENT
   (`getSchoolDetail` option `hideStaffEmails`).
3. Medium. `admins/route.ts` POST: the target must be a TEACHER or ADMIN (400 otherwise). The target lookup
   is already scoped to the school of the caller by TenantDB.
4. Medium. `admins/route.ts` POST and `admins/[adminId]/route.ts` DELETE: the owner-only rule locked out
   4 of 8 migrated schools. Now `canManageSchool` (owner, ADMIN of the school, SYSTEM).
5. Medium. `server/models/classroomModel.ts` `getAllStudentsByAdmin`: returned `[]` without a
   `school_admins` row. Now it scopes by the school id that the controller authorized. Route:
   `GET /api/classroom/students` via `classroomController.fetchStudentsByRole`.
6. Medium. `app/api/classrooms/route.ts`: the `schoolAdminRows` query read `user_roles` by user id twice.
   Any user with one `user_roles` row passed the second gate. The query is removed; `assertCan` and the
   `users.role` check decide.
7. Other uses of `schoolAdmins` or `school.ownerId` as the only gate (grep of `server` and `app/api`):
   - `server/utils/auth.ts` (`validateUser`, `effectiveCallerRole`, `loadTargetEffectiveRank`): a
     `school_admins` row only raises the rank next to `users.role`. Not a sole gate. No change.
   - `server/models/teacherModel.ts` line 498: inserts a `school_admins` row on admin creation. No gate.
   - `server/models/schoolModel.ts` `getSchoolDetail`: reads the rows for display. No gate.
   - `app/api/users/me/school/route.ts` DELETE: owner-only by design (destroys the school). Kept.
     Gap: an ownerless school cannot be deleted by its ADMIN. Only SYSTEM tools can.
   - `app/api/upload/csv/route.ts`: the `ownerId` there is a class teacher id. Not a school gate.
