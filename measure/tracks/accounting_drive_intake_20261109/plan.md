## Rules for this plan

- Markers: `[ ]` pending, `[~]` in progress, `[x]` done. An `[x]` note names the commit and the evidence class: automated, person-checked, or owner-passed.
- Each task follows `measure/workflow.md`: tests first, then code, then one commit with `(track_id: accounting_drive_intake_20261109)`. The header is 100 characters or less.
- Stage named paths only. Other sessions commit on master. Never run `git add -A` or `git add .`.
- Every Green task that writes code has a Red task before it. A Red task holds the test file only.
- Tests use fakes only. No real finance document and no real amount enters git, a test, a log, or a non-Vertex model route (never the Aliyun plan, never OpenRouter).
- No new hash field, no checksum column, and no manifest (AGENTS.md hashing policy).
- **Start gate.** The build code starts after 2026-11-20. An earlier start uses only a slot that Storytime does not need. Before 2026-11-20 this track holds spec and plan work only. The PM first load of 2026-11-10 and the PM structure report of 2026-11-11 are PM tasks in Phase 5. They run the PM's own script on this machine, they use no code of this track, they write no row in the accounting database, and they do not wait for the gate (PM-5, PM-7, D-19).
- Every new Drizzle table is classified in `packages/domain/src/tenant-registry.ts`. Default classification is `EXEMPT`.
- Business logic lives in `packages/backend/src/modules/accounting`. Route handlers stay thin. Provider SDKs stay behind adapters.
- The intake folder is Daniel's existing Drive folder `Accounting`. The poll reads its top level and, from 2027, the subfolder of the current year. The poll never reads the `2024` and `2025` folders. The folder id comes from `ACCOUNTING_DRIVE_FOLDER_ID`; no id enters git.
- A deferred task is marked `deferred:pm` or `deferred:daniel`. It carries no code in this track.
- Spec section 14.1 (PM-1 to PM-7) and section 14.2 (D-1 to D-35) are DECIDED. A task does not reopen a decision from those sections; a change needs a new PM or orchestrator answer.
- Spec section 14.2 marks the first D-7 SUPERSEDED in place and keeps one current D-7 (F57). One D-11 entry remains (F63).
- A quote of Daniel's words writes a role in square brackets in the place of a person's name, for example `[the CEO]` (D-31, PM decision 14:1x).

## Notes for the implementer

- The idempotency key is the Drive file id. The unique index is scoped by company, submitter, and key (`packages/db/src/accounting/schema/index.ts:102-106`). The poll runs as one stable account (open item Q3).
- The content-duplicate lookup of section 5.5 is a byte-only scan through `sameEvidenceBytes`. It never reads the parsed scalar fields, and it covers the history rows (F48, PM-7). The same-key replay reaches the private `hasSameSubmissionContent` inside `submitAccountingSubmissionWithOutcome`; no export is needed.
- The CSV export route and its ten headers stay byte-identical (`apps/accounting/app/api/submissions/export/route.ts:31-76`), and its own role test at `:35` is the one named exception to FR-8.
- `ALTER TYPE ... ADD VALUE` cannot run inside a Drizzle migration transaction (lessons-learned, 2026-08-20). The action columns are `text` with check constraints, so widen or add a check with `DROP CONSTRAINT` and `ADD CONSTRAINT` in one migration. The close audit trail is a new table, so the submission audit table needs no change.
- The durable job tables live in the main product database (`packages/db/src/schema/jobs.ts:44`). The accounting poll does not reuse them. It uses the lease row of FR-6 and the Cloud Run job `accounting-intake-poll` (decision D-12).
- The Cloud Run job image carries **one self-contained** Node file. The Dockerfile builds `app/lib/intake-runner.ts` into `dist/intake-runner.mjs` with `esbuild@0.28.1`, the version the lockfile already resolves at `pnpm-lock.yaml:10067`. The command is a **full bundle**: it holds `--bundle --platform=node --format=esm --target=node22` and a `createRequire` banner, and it holds **no `--packages=external`**. The **existing web stage** stays the last stage and copies that one file with one added `COPY --from=runner-bundle` line; it starts `CMD ["node", "apps/accounting/server.js"]`, which stays the image default. The Cloud Run job uses the same image and sets `--command=node --args=dist/intake-runner.mjs`. No new final stage and no second stage named `runner` (F67, F68, D-32). The bundle must be self-contained: an externalized import would fail with a missing module (F55, D-27). Cloud Scheduler starts the job through the Cloud Run Admin API `jobs.run` endpoint with an OAuth token, never a `run.app` job URL.
- **IAM grants belong to the PM.** The two scheduler grants are `deferred:pm` steps in the runbook or the account console. No **new** grant step for them goes in `cloudbuild.yaml`, in a build step, or in a Green task (F73, D-20). The existing `allow-build-invoker` `add-iam-policy-binding` step at `apps/accounting/cloudbuild.yaml:48-57` stays unchanged; the rule is not a ban on that step (F76).
- The bundle command's `--outfile` is the absolute path `/app/dist/intake-runner.mjs`, equal to the web stage's `COPY` source. `pnpm --filter accounting exec` runs with cwd `/app/apps/accounting`, so a relative `--outfile` lands in `/app/apps/accounting/dist` and the build fails. The web stage's `WORKDIR` is `/app`, so the job arg `dist/intake-runner.mjs` resolves (F75, D-35).
- `evidence_byte_size` is the byte length of the downloaded Drive file buffer, set by the intake `insert`. The table is new, so no backfill is needed. A submission typed by hand has no intake row, so pass 2 does not cover it and pass 1 (the newest 500) does (F69, D-33).
- **Every** Secret Manager reference goes through `--set-secrets` in the `NAME=SECRET_NAME:latest` form, exactly as `apps/accounting/cloudbuild.yaml:40` does for the web service: `ACCOUNTING_DATABASE_URL`, `STORAGE_ENDPOINT`, `STORAGE_REGION`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, and `STORAGE_PUBLIC_BASE_URL`. Only the plain values go through `--set-env-vars`: `ACCOUNTING_DRIVE_FOLDER_ID`, `ACCOUNTING_INTAKE_ACTOR_ID`, `ACCOUNTING_DUPLICATE_SCAN_CAP`, and `ACCOUNTING_EXTRACTION_MODEL`. A `:latest` token in `--set-env-vars` is a defect (F56).
- The content-duplicate lookup runs two passes: pass 1 by recency with the cap, pass 2 by `evidence_byte_size` with no cap. Pass 2 is what makes the PM-7 condition hold for every history row (D-28). `evidence_byte_size` stores a byte length, never a hash.
- `submitAccountingSubmissionWithOutcome` is the one writer of the submit audit row. The intake `insert` writes the intake row only (D-29).
- The first live month is `FIRST_LIVE_MONTH = "2026-11"`, a code constant in `packages/backend/src/modules/accounting/monthly-close.ts` (D-30).
- Red-phase commits hold only the test file and the Measure doc edits. Check `git status --short` before every commit (lessons-learned, `ci_typecheck_alignment_20260603`).
- The Vertex path uses Application Default Credentials (PM-3). No `VERTEX_CLIENT_EMAIL` and no `VERTEX_PRIVATE_KEY` is set for this track. `VertexProviderConfig` at `packages/ai/src/providers/vertex.ts:7-18` makes both fields optional.
