## Summary of Changes

All changes in the last 24 hours are in **Primary Advantage Phase 1**. No code changes were made for Reading, CodeCamp, Sales, or the shared packages (`@reading-advantage/api`, `@reading-advantage/domain`, `@reading-advantage/webhooks`) in this window.

Primary changes include:

1. **Game completion crash guard (M1)** — `components/lesson/games/lesson-sentence-order-word.tsx` and `components/pratice/order-words-game.tsx` now destructure `{ user, session, update }` from `useSession()` via a typed local fallback, preventing `ReferenceError` when the completion callbacks invoke `update(...)` or read `session?.user`.
2. **Admin student CRUD live calls (M2/M3)** — `app/[locale]/admin/students/page.tsx` now issues real `POST /api/students`, `PUT /api/students/:id`, and `DELETE /api/students/:id` requests and reconciles server responses before updating local state, replacing the previous optimistic-only local mutations.
3. **Flashcard shared-schema contract (M6)** — `actions/flashcard.ts` no longer writes the 19 shared-partial FSRS/content columns to `flashcardCards` and no longer uses `as any`. FSRS scheduler state is persisted in the existing `flashcardProgress` table; review history continues to go to `cardReviews`; content metadata is recovered at read time from `articles` joined to `sentencs_and_words_for_flashcard`.
4. **Dashboard fabricated metrics removed (M11)** — `app/[locale]/admin/dashboard/page.tsx` replaces hard-coded `100`/`5`/`100%` metric cards with explicit "Data unavailable" placeholders and notes that live wiring is pending the multi-tenant scoping track.
5. **Red tests added** — Five new test files were committed in `1433a9eb` covering each of the above workflows. `package.json` gained the expected Testing Library and jsdom dev dependencies.
6. **Plan updated** — `plan.md` Phase 1 tasks are now marked complete with Green evidence notes; auth/tenant route sweep is explicitly deferred with the `deferred:phikul` tag.

## Code Quality Observations

- **Positive:** The Red → Green cycle is clearly evidenced, tests are committed before the fix, and the new tests pass against the implementation.
- **Positive:** `actions/flashcard.ts` removes all `as any` casts on the shared-schema insert/update paths and moves FSRS state to an existing table, avoiding a schema migration while preserving behavior.
- **Positive:** Admin CRUD handlers now await server responses and fall back to `fetchStudents()` for legacy response shapes, which is a low-risk migration strategy.
- **Caution:** The `useSession()` fix relies on a local `as unknown` cast to inject `session` and `update` bindings that the auth-client contract does not actually expose. This stops the crash but is a stub, not a real session refresh. The inline JSDoc documents this, but the behavior is effectively a no-op when the underlying hook does not provide these fields.
- **Caution:** Several renamed local identifiers (`deckKind`, `sourceArticleId`, `cardRows`) improve clarity, but the `flashcardDecks.type` column is now sometimes referred to as `kind` in code comments and return shapes while the DB column remains `type`, which may confuse future consumers.
- **Caution:** The flashcard read helpers (e.g., `loadArticleSnapshot`) use `sentRows[0]` for audio URLs in multiple game types; this is acceptable for the representative slice but should be reviewed when the same pattern is propagated.
- **Caution:** `handleAddStudent`/`handleUpdateStudent` only `console.error` on failure and do not surface user-facing error states.
