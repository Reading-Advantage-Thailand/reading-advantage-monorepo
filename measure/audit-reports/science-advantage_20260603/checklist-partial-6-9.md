| 6.3 | Env vars validated at boot via Zod; missing/invalid env causes process exit | **PARTIAL PASS** | `lib/env.ts` exists (29 lines) and runs `envSchema.parse(process.env)` at module load — a top-level statement that throws on invalid env. **Coverage is incomplete**: schema only validates 5 vars (`DATABASE_URL`, `NODE_ENV`, `NEXT_PUBLIC_ENABLE_MASTERY_PIPELINE`, `DEV_AUTH_ENABLED`, `REDIS_URL`). `.env.example` lists **22+ vars** including `DIRECT_DATABASE_URL`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `AI_RECOMMENDER_*` (8 vars), `AI_IMAGE_*` (3 vars), `GOOGLE_CLOUD_*` (3 vars), `NEXT_PUBLIC_FEATURE_AI_RECOMMENDATION`, `NEXT_PUBLIC_STRUCTURED_CONTENT_ENABLED`. Marked PARTIAL because the boundary file exists and is used, but it does not cover the env surface declared in `.env.example`. |
| 6.4 | Types inferred from Zod (`z.infer`) — no parallel hand-written types | **PASS (with 1 nuance)** | 28 `z.infer<...>` uses across the app. Representative: `lib/schemas/lesson-content.schema.ts:266–283` (16 types), `lib/validations/class.ts:32, 44, 60, 79` (4 types), `lib/schemas/seed-validation.ts:69–72` (4 types), `lib/validations/student-classes.ts:36, 42` (2 types). No hand-written `type X = {...}` duplicates observed for the audited schemas. **Nuance:** `createClassSchema` (server) and `createClassFormSchema` (form) are *two* distinct Zod schemas, not one — the form variant uses `z.coerce.number().pipe(serverSchema.shape.gradeLevel)` to bridge the form-input string to a server number. This is a legitimate separation (form has different parsing rules) rather than a parallel hand-written type, so it is still PASS. |
| 6.5 | AI structured outputs use `generateObject` + Zod schema; no `JSON.parse(aiText)` | **PASS** | `lib/ai/recommendation-service.ts:2, 16–32, 79` — `recommendationSchema` is a Zod object, passed as `schema:` to `generateObject` from the Vercel AI SDK. The `JSON.parse(cached)` at line 95 parses a **cache** value (Redis string), not raw AI text; the `try/catch` is the documented fallback for corrupted cache entries. The `JSON.stringify(result)` on lines 138, 163 are write-sides, not read-sides of AI output. No `JSON.parse` of AI text was found. |
| 6.6 | Forms on the client use the same Zod schema as the server (shared via `packages/types` or `@reading-advantage/contracts`) | **PARTIAL PASS (nuanced)** | Sampled 2 form components. (a) `components/features/student/join-class-form.tsx:24–27, 75` imports `joinClassSchema` from `@/lib/validations/class` — the **exact same** schema used by the server at `app/api/classes/join/route.ts:10, 44`. ✓ (b) `components/features/classes/create-class-form.tsx:28, 88` imports `createClassFormSchema` from `@/lib/validations/class` — a *form-specific* schema (line 50) that pipes through `createClassSchema.shape.gradeLevel` to bridge string→number. The form and server share the **same field constraints** but use two distinct schemas. The schemas live in the app (not in `packages/types` or `@reading-advantage/contracts`) — there is **no shared contracts package** in this monorepo. PASS for "same Zod schema" intent (no drift in constraints); DEFER for "shared via `packages/types`" since that package does not yet exist. |

## Section 9 — Observability

> *AGENTS.md §Observability*

| # | Check | Status | Evidence |
|---|-------|--------|----------|
| 9.1 | All backend functions emit structured logs with `requestId`, `userId`, `operation`, `latencyMs` | **PARTIAL PASS** | A structured-logger surface exists at `lib/observability/logger.ts` (38 lines) — `logger.{info,warn,error}(event, payload)` with a `LogPayload` type that wraps `Record<string, unknown>`. Output is JSON-shaped: `{ event, level, timestamp, ...payload }` (line 6–11). **However, the logger does NOT propagate `requestId` or `latencyMs` automatically** — the caller must add them. The 5 largest route.ts files (`update-mastery/route.ts`, `lessons/.../quiz/route.ts`, `lessons/.../analytics/route.ts`, `assignments/route.ts`, `recommendations/route.ts`) emit **zero** structured logs in their hot paths (the AI handlers do emit `logger.*` calls — credit there). The smaller routes that do call `logger.info/warn/error` (e.g. `teachers/.../intervention-alerts/route.ts:264, 278`, `students/[studentId]/achievements/route.ts:48, 57`, `students/[studentId]/gamification-profile/route.ts:100, 111`, `students/me/gamification/route.ts:94, 106`, `students/[studentId]/mastery-profile/route.ts:286, 310`, `ai/update-mastery/route.ts:265, 296, 476, 487, 526, 571, 582`, `ai/recommendations/route.ts:93, 382`) include `studentId` and `model` but not `requestId` / `userId` / `latencyMs`. No automatic request-context middleware exists. |
| 9.2 | No `console.log` / `console.error` in production code (test files OK) | **FAIL — count: 67** | `rg -n 'console\.(log\|error\|warn\|info)' apps/science-advantage/{app,lib,components}/ proxy.ts` (excluding `*.test.*` and `__tests__/`) returns **67 hits** in production code. Distribution: `app/` 25 (mostly `app/api/**/route.ts` catch blocks, all `console.error`); `components/` 30 (mostly `console.error` from `fetch().catch()` handlers; 4 `console.log("[Telemetry] ...")` in `components/features/teacher/intervention-alerts-widget.tsx` lines 301, 320, 347, 360; 1 `console.info` in `components/features/student/ai-recommendation-card.tsx:226`); `lib/` 8 (3 in `lib/observability/logger.ts` which is the structured logger's console-sink; 1 in `lib/observability/metrics.ts`; 1 in `lib/analytics.ts`; 1 in `lib/utils/clipboard.ts`; 2 in JSDoc example blocks in `lib/schemas/lesson-content.schema.ts`); `proxy.ts` 3 (all `console.error`). Per the protocol, **10+ console.* in production = Medium**; 67 = decisively above the bar. |
| 9.3 | Error reporting (Sentry, OpenTelemetry, equivalent) is wired and captures unhandled errors | **FAIL** | No `Sentry`, `@sentry/*`, `opentelemetry`, `OTLP`, `@opentelemetry/*` package or runtime reference found in `apps/science-advantage/`. The 6 matches that surfaced are all in **archive docs** (`docs/archive/architecture/error-handling.md:567, 568, 739, 741, 742`, `docs/archive/onboarding/environment.md:73`) — historical guidance, not active code. No `instrumentation.ts` file at the app root (Next.js convention), no `sentry.client.config.ts` / `sentry.server.config.ts`. The structured logger (`lib/observability/logger.ts`) just calls `console.error/warn/info` — no upstream error reporter. |
| 9.4 | Audit events are written for: login, logout, password change, permission change, billing event, destructive action | **FAIL** | No audit-log table exists. `rg -n 'auditLog\|audit_log'` over `packages/db/src/schema/` returns **0 matches** — the only `audit` mention in `packages/db` is a comment in `__tests__/schema-parity.test.ts:1` ("...classified as PORT or UNIFY in audit.md") referring to a porting-decision doc, not a table. No `audit.*login\|audit.*logout\|audit.*password` in `apps/science-advantage/`. Historical Prisma-era references in `docs/archive/architecture/security-performance.md:262, 277` describe an aspirational `lib/audit.ts` and `prisma.auditLog.create({...})` — but neither exists in current code. Auth events are logged via `logger.info(...)` only inside the 4 stub `app/api/auth/{impersonate,login,logout,session}/route.ts` files — but those are 6-line placeholder files; no actual login/logout/password-change handler runs through them. Real auth lives in `proxy.ts` and `lib/auth/`, neither of which writes audit events. |
| 9.5 | Audit log table is append-only (no UPDATE/DELETE grants in DB migrations or app code) | **FAIL (N/A precursor — table does not exist)** | Vacuously true that no UPDATE/DELETE on a non-existent table is impossible; the rule is moot until 9.4 lands. Recording as FAIL to flag the gap. |
| 9.6 | Request tracing enabled for at least the API surface | **FAIL** | No `trace(`, `span(`, `opentelemetry`, `@opentelemetry/*` matches in `apps/science-advantage/`. The only `traceId` references are in `lib/ai/recommendation-service.ts:97, 126, 144, 153` — a context field plumbed through the AI pipeline, **not** a distributed-trace span; it is generated elsewhere and never tied to the HTTP request. No `withTracing` / request-context middleware wrapping route handlers. No `instrumentation.ts` registration with `@vercel/otel` or equivalent. |
