## Independent source reconstruction

1. Resolve every source with `git show <revision>:<relative-path>` from the
   frozen source commit. Never use the working tree, generated prose, graph
   records, v2 hashes, or mapper conclusions as source truth.
2. Compute each whole-blob SHA-256 directly from the returned bytes.
3. For text citations, split the same bytes with line terminators retained,
   concatenate the declared inclusive lines, and hash those exact bytes. Do not
   synthesize a final LF. For PNG records, hash the whole binary blob and check
   the PNG signature.
4. Limit facts to exact literals, expressions, calls, branches, or test-source
   structure in one declared envelope. Keep interpretation and runtime limits
   separate. Conjunctive `required_substrings`, exact test-block counts, binary
   signatures, and the directory-object fixture are standalone-verifier inputs.
5. Verify the complete accepted configuration source and both accepted test
   sources as whole blobs. The 13 test claims cover all 53 named `it` blocks:
   12 in the component test and 41 in the model/config test. Test claims record
   test-source structure or intent only, never production execution.
6. Re-derive all four fixtures: bounded semantic overstatement, invalid tree
   citation, fabricated Redis/success behavior, and keyword-only responsive
   inference. Fixtures remain excluded from factual totals.

## Standalone verification contract

The standalone Python verifier is intentionally external to the four allowed
outputs. It parses the v3 ledger and, for every claim and fixture:

- resolves the declared Git object;
- compares the whole-blob SHA-256;
- recomputes the exact range SHA-256 under the declared newline convention;
- checks required/forbidden substrings, exact test-block counts, or PNG magic;
- verifies the invalid primary directory resolves to a Git `tree`;
- checks every whole-source coverage byte count, line count, and blob hash;
- checks unique claim IDs and fixture dispositions.

The first draft run correctly found four newly typed range digests and one test
count that did not match recomputation; they were corrected from the verifier's
fresh source results. The final standalone run checked 89 claim/fixture/source
envelopes and 220 semantic assertions with **0 mismatches**. The final report
states zero only for that final clean run.

## Semantic and runtime limits

Catalog `playable`, CSS classes, component tests, canvas source, route factories,
and result UI do not prove browser behavior, trusted input, foreground timing,
successful completion, persistence, idempotency, or XP award. The accepted B4
direction remains external context: Village Guardian was observed with
`isTrusted=false` synthetic input and hidden-tab scheduler limits, and its
completion POST returned HTTP 400. This collector performed no browser run and
preserves those completion/browser facts as unknown or non-successful here.
PNG presence and the catalog cover reference do not establish live resource
loading or suitability. Accessible gameplay semantics and pre-baseline
chronology also remain unknown.
