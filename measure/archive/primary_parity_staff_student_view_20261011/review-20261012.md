## Verification (a): avatar read path performs no writes — PASS

`getAvatarState` grants the starter set only for a student writer
(`packages/domain/src/primary-avatar/shop.ts:121`):

```ts
if (profile && canWriteStudentRecord(ctx.user)) await ensureStarterSet(...)
```

Staff skip `ensureStarterSet`. The write functions keep their own assert:
`purchaseAvatarItem` (`shop.ts:200`) and `setLoadout` (`shop.ts:245`)
call `assertStudentRecordWriter`. The avatar and shop pages never call
`getAvatarState` for staff: the avatar page loads `null` profile for staff
(`student/avatar/page.tsx:60-61`), and the shop page uses
`previewHeroProfile()` with zero coins (`student/avatar/shop/page.tsx:36`).
The home page skips the avatar read for staff (`student/home/page.tsx:145`).
The quest battle page returns before its avatar read for staff
(`student/quest/battle/page.tsx:46-59`). The game pages gate the avatar
read on a student `ownerKey` (`student/games/apk/[cartridgeId]/page.tsx:49-53`).

## Verification (b): preview pages never call GET /api/v1/avatar — PASS

No preview page fetches `GET /api/v1/avatar`. A grep over `app/` and
`components/` (excluding tests) finds only two avatar fetches, both POST:
purchase (`components/avatar/avatar-shop.tsx:118`) and loadout
(`components/avatar/avatar-home.tsx:42`). Both routes refuse staff with
403 `PREVIEW_READ_ONLY` before parsing the body
(`app/api/v1/avatar/purchase/route.ts:14-15`,
`app/api/v1/avatar/loadout/route.ts:14-15`). Both buttons are off in
preview with the "Preview: not saved" note. Pages read avatar state
through the domain on the server, never through the route. The route
itself refuses staff (`app/api/v1/avatar/route.ts:14-15`), so a raw
fetch from client code also gets 403 with no mutation.

## Verification (d): the sample-input games fix saves nothing — PASS

`c509cf8b1` changes `getLessonGameInputAction` only: staff without a
class book get the sample set from `listPrimarySamplePracticeInput`
(`apps/primary-advantage/actions/lesson-games.ts:34-38`). That function
reads the newest published articles and no user row, and writes nothing
(`packages/domain/src/games/primary-saved-items.ts:437-456`). It uses

global and the query touches no tenant row. The class-book proof path
stays for the projector, and students are unchanged. Completion still

`save={false}`: the apk page (`page.tsx:62`), the story page, and the
lesson task games via `save={!isPreview}`
(`components/lesson/lesson-progress-bar.tsx:439,447`). The host
returns before posting when `save` is false
(`components/games/game-host.tsx:165`). Double protection holds:
client skip plus server 403.
