# Specification: APK Planned/New-Game Intake

## Objective

Define evidence-first intake for a future APK game without adding a title to the accepted legacy denominator or authorizing a placeholder.

## Requirements

- Require a product-owner-approved identity, learning objective, content contract, mechanic evidence, capability assessment, semantic role/state requirements, physical behavior descriptors, suitability/ingestion decision, and host/retirement boundary before a child implementation track may be proposed.
- Reject placeholder titles, generic sample games, speculative catalog entries, routes, cartridge code, and asset mappings.
- Keep future games outside the 27/29 legacy reconciliation ledger until their separately approved intake is accepted.

## Acceptance criteria

- The intake schema fails closed for missing evidence or placeholder identity.
- An accepted intake produces only a bounded implementation-track proposal, never an implementation authorization.
