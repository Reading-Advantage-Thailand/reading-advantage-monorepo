## Code quality observations

### Strengths
- **TDD discipline:** Red tests preceded green implementation for Zod schema, GET list handler, and project persistence.
- **Live behavior proof:** PGlite integration tests provide genuine Postgres round-trips (INSERT/SELECT, JSONB persistence, campaign scoping) rather than relying solely on mocked DB chains.
- **Security hygiene:** The API-key redaction fix in `test-connection/route.ts` closes a real secret-exposure vector where upstream SDK error messages echoed the caller's key.
- **Honest closeout:** The plan and metadata truthfully record the build blocker and manual QA deferral instead of marking everything `[x]`.
- **Schema reconciliation:** Marketing schema tests were corrected to reference the canonical `0021_sales_advantage.sql` migration, removing a stale artifact/drift issue.

### Concerns
- `apps/marketing/app/lib/ai` remains an app-local AI client, diverging from the shared `packages/ai` adapter. The spec's non-functional note flags this as a future consolidation candidate.
- `generate-script/route.ts` still parses LLM output with `JSON.parse` before schema validation; malformed JSON will throw an unhandled 500. The plan's risk register notes this but no retry or structured-error path was added.
- The PGlite test harness (`testDb.ts`) duplicates a subset of the marketing DDL. If the canonical schema changes, the harness could drift. A generated-schema sync check would reduce maintenance risk.
- Component tests in `phase-7-video-page.test.tsx` mock `fetch` and `useParams`; this is appropriate for jsdom but still leaves real drag-and-drop interactions as manual-QA scope.
