### LR-primary-advantage-024-001 — Server response includes `pagination` but the table only renders the first page; no "load more" or page controls

- Severity: High
- Fork-divergence category: Fork-specific regression
- File: `apps/primary-advantage/components/admin/teachers-table.tsx:111-136,617-720`, `apps/primary-advantage/server/controllers/teacherController.ts:62-69`
- Evidence: `fetchTeachers` (lines 111-136) calls `GET /api/teachers` with no query parameters, and the server's `getTeachersController` (controllers/teacherController.ts:44-47) defaults `page=1, limit=50, search="", role=""`. The controller constructs a `pagination` object (lines 62-69) with `page, limit, total, totalPages` and returns it as part of `TeachersResponse`. The client casts the response to `TeachersResponse` (line 120) and stores `data.teachers` and `data.statistics` in state (lines 128-129) but never reads `data.pagination`. The table render (lines 617-720) iterates `filteredTeachers` (which is `data.teachers` — line 178) with no page controls, no "load more" button, no `total` count, and no awareness that more rows exist. The `search` query parameter accepted by the server (line 47 of route.ts) is also never sent by the client.
- Impact: High. For any school with more than 50 teachers, the admin sees only the first 50 records and has no indication that more exist. The server deliberately returns a `pagination` object that the client silently discards. This is the same class of contract-drift bug as LR-023-002 (controllers/teacherController.ts vs page) — the server returns a structured field that the UI ignores. The `search` parameter is also unused, meaning an admin typing in the search box (line 378-382) only filters the first-50 in memory.
- Recommendation: Read `data.pagination` (line 129) and store `pagination` in state. Add a `loadMore()` function that increments `page` and appends to `teachers`. Render a "Load more" button or pagination footer at line 718-720 with the `total` count. Send the `search` parameter from the client: change the fetch URL on line 114 to `/api/teachers?search=${encodeURIComponent(searchTerm)}&page=1&limit=50` and refetch on debounced searchTerm change. Add a server-side Zod schema for the query parameters to enforce `page >= 1`, `limit <= 100`, and `search.length <= 200` at the boundary.

### LR-primary-advantage-024-012 — `locale as "th" | "cn" | "tw" | "vi"` type assertion lies to TypeScript; adding a new locale silently breaks localized summary

- Severity: Medium
- Fork-divergence category: Intentional product divergence that needs documentation
- File: `apps/primary-advantage/components/articles/article-card.tsx:27-36`
- Evidence: `getLocalizedSummary` (lines 27-36) checks `if (!locale || locale === "en")` first (line 28) and falls through to the translated summary otherwise. The translation key access on line 33 uses `article.translatedSummary?.[locale as "th" | "cn" | "tw" | "vi"] || article.summary`. The `as` assertion tells TypeScript that `locale` is one of the four union members, but at runtime `locale` is whatever `next-intl` returns (a string). If a new locale is added to `i18n/routing.ts` (e.g., "ja" for Japanese, "ko" for Korean), the routing returns "ja", the type assertion is a lie, the bracket access returns `undefined`, and the `||` falls through to `article.summary` (English). The user sees English summary on a Japanese-localized page with no console warning. The `Article` interface in `types/index.d.ts:6-12` hardcodes the four locales in the `translatedSummary` shape, so any new locale is a type-system no-op until the interface is also updated.
- Impact: Medium. The type system and the runtime contract are decoupled by the `as` assertion. A new locale silently degrades to English summary instead of failing loudly. The same hardcoded union appears in `types/index.d.ts` (line 6-12) and would need to be updated in three places: routing, types, and the `as` cast.
- Recommendation: Replace the type assertion with a runtime check: `const supportedLocales = ["th", "cn", "tw", "vi"] as const; type SupportedLocale = typeof supportedLocales[number]; const summaryLocale = supportedLocales.includes(locale as SupportedLocale) ? (locale as SupportedLocale) : "en"; return article.translatedSummary?.[summaryLocale] || article.summary;`. Better: drive the supported-locale list from a single source (e.g., a `SUPPORTED_LOCALES` constant in `i18n/routing.ts` or a new `lib/locales.ts`) and derive the union type from it. Define `translatedSummary` in the `Article` interface as a `Record<Locale, string> | null` instead of an inline union, and iterate the same `SUPPORTED_LOCALES` constant for translation-key construction.

### LR-primary-advantage-024-013 — Provider Neutrality Rule violation: `getArticleImageUrl` builds a public GCS URL directly, bypassing the shared storage adapter (`storage.getSignedUrl()`)

- Severity: Medium
- Fork-divergence category: Fork-specific regression
- File: `apps/primary-advantage/components/articles/article-card.tsx:15,38`, `apps/primary-advantage/lib/storage-config.ts:6-33`
- Evidence: Line 15 imports `getArticleImageUrl` from `@/lib/storage-config`. The implementation in `lib/storage-config.ts:6-9` defines `STORAGE_CONFIG = { bucketName: process.env.STORAGE_BUCKET_NAME || "primary-app-storage", baseUrl: "https://storage.googleapis.com" }` and `getArticleImageUrl(articleId, imageNumber)` (lines 28-33) returns a public GCS URL of the form `https://storage.googleapis.com/primary-app-storage/images/${articleId}_${imageNumber}.png`. The root AGENTS.md ("Storage" section) and the provider-neutrality rule require: "Application code should call storage.getSignedUrl() ... Application code must not directly call storage provider SDKs." The local `lib/storage-config.ts` is a hand-rolled URL constructor, not the shared storage adapter from `@reading-advantage/storage`. The article-card uses this URL on line 38 to obtain a public, unauthenticated GCS URL — fine for public images, but the implementation pattern bypasses the adapter.
- Impact: Medium. The same `lib/storage-config.ts` is used by other components (e.g., `app/[locale]/admin/dashboard/page.tsx` references for image rendering). Note: the `imageUrl` is also declared on line 38 but never used in the JSX (see LR-024-014), so the dead code is also a provider-neutrality violation waiting to be wired in.
- Recommendation: Move the storage URL construction into the shared `@reading-advantage/storage` adapter as `storage.getPublicUrl(path)` (for public assets) and `storage.getSignedUrl(path, { expiresIn: 3600 })` (for private assets). Replace the `lib/storage-config.ts` import on line 15 with the adapter call. Drop the hand-rolled `STORAGE_CONFIG` constant from `lib/storage-config.ts` or have the adapter read the same env var. Document in `apps/primary-advantage/AGENTS.md` that article images are public assets (so `getPublicUrl` is the right call) and that audit logs / private user data must use `getSignedUrl`.
