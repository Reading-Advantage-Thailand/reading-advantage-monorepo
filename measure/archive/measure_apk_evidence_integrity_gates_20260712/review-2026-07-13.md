## 3. Code quality observations

- **Strengths**
  - Fail-closed by default: unknown schema versions, missing baselines, placeholder provenance, disabled stop triggers, and unavailable live exports all return stable rejection codes rather than warnings.
  - Content-addressed artifacts: SHA-256 hashes bind candidate, review, approval, consumption, and accepted manifests; gzip snapshots are hash-verified before parsing.
  - Immutable source binding: allowed-input entries can pin a Git revision and resolve bytes from the commit object, preventing plan updates from invalidating frozen inputs.
  - Comprehensive mutation coverage: supervisor integration tests include tamper, forgery, replay, early approval, inherited message, truncated retained export, symlink traversal, and dirty-worktree cases.
  - Clean separation of concerns: contract scaffold, claim validation, denominator/roles, lifecycle, and supervisor gate are modular files with stable public surfaces.
  - Plan markers are strictly `[~]`, `[x]`, or `[b]`; no legacy `[ ]` space markers remain.

- **Weaknesses / nitpicks**
  - `contracts.py` mixes Phase 0 scaffold constants with retry validators and Phase 2 immutable-source logic; at >1,100 lines it is larger than ideal, though the public surface is frozen.
  - Some acceptance evidence paths still reference the historical `measure/tracks/...` location. The closeout manifest acknowledges these as static historical records with no runtime dependency (A9 findings).
  - The v8 gate commit (`5aea360f`) is a pre-v8 state commit; the final accepted manifest binds that exact commit rather than the final closeout commit. This is intentional per the plan (gate must be frozen before product execution), but it means the closeout commits are not themselves part of the consumed gate file set.
