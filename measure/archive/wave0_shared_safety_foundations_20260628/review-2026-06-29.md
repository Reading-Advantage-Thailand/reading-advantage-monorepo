## Summary of changes

The last 24 hours delivered the implementation (Phases 1–4) of Wave 0. The commits are tagged with the track ID and cover:

- **Phase 1 — Tenant registry and fail-closed TenantDB**
  - Classified all 92 exported Drizzle tables in `packages/domain/src/tenant-registry.ts` (9 previously unclassified tables now have explicit FLAT / REFERENTIAL / EXEMPT labels).
  - Made `TenantDB` fail closed for null-tenant FLAT operations in `packages/domain/src/db-contract.ts`.

  - Refactored auth rate limiting to a Postgres-backed store (`packages/auth/src/rate-limit-store.ts`, `login_attempts` table, migration `0024_futuristic_vulture.sql`), with a dev-only opt-in in-memory fast path.
  - Wired `packages/api/src/routes/auth/login.ts` to extract client IP and use the durable limiter.

- **Phase 3 — Shared contracts and typed error boundaries**
  - Added shared envelope schemas in `packages/types/src/contracts/envelopes.ts`.
  - Added shared sales output schemas in `packages/types/src/contracts/sales.ts` and tightened branded ID schemas (`PolymorphicQuestionId`, `ExternalLessonId`) to reject empty strings.
  - Adopted `createClassSchema` from `@reading-advantage/types` in `packages/api/src/routers/classes.ts`.
  - Replaced string-based error mapping in `packages/api/src/routers/sales.ts` and `packages/api/src/routers/users.ts` with `instanceof` checks against typed domain errors (`ScenarioNotFoundError`, `UserNotFoundError`, etc.).

- **Phase 4 — Transport-thin shared API boundary**

  - `packages/api/src/routers/reports.ts` now delegates all procedures to domain functions and contains zero Drizzle/schema imports.
  - Rewrote `packages/api/src/__tests__/reports.test.ts` and updated `users.test.ts` to assert delegation and transport mapping only.

## Code quality observations

- **Tenant registry:** Classifications are explicit and include audit-friendly comments. The `requireTenantForFlat` helper is placed at the right choke points (select `.from`, update, delete, insert).
- **Error mapping:** The switch from string-sniffing to `instanceof` checks is a clear improvement. Two cross-school / own-profile forbidden cases in `users.ts` still use string matches, but the plan explicitly notes these as out of scope for this wave.
- **Rate limiter:** The store seam is clean; production defaults to Postgres and the in-memory fast path is gated by both `NODE_ENV === 'development'` and `RATE_LIMIT_INMEMORY_FASTPATH === 'true'`.
- **Router boundary:** `reports.ts` is now a thin transport layer. The static guard tests in `api-architecture-boundary.test.ts` will prevent future regressions.
- **Tests:** New tests are behavior-driven and follow the red-green pattern documented in the plan. A few lint warnings remain in touched packages but no new lint errors were introduced.
