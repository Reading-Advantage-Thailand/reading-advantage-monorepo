## 1. Summary of changes

The track delivered fixes for every blocker and systemic issue surfaced in the 2026-07-07 unpublished-games review:

- **4 game-breaking bugs fixed and live-verified:**
  - `griffin-riders-escape`: main `requestAnimationFrame` loop now re-arms itself; the Konva stage measurement effect re-runs once `gameState` exists so the container ref is attached before metrics run.
  - `haunted-library`: the next-frame schedule moved out of the `setGameState` updater, eliminating the exponential rAF storm caused by StrictMode double-invocation.
  - `abyssal-well`: spawn bookkeeping (`lastSpawnRef`) moved out of the state updater; previously StrictMode's discarded first invocation consumed every spawn window and no enemies appeared.
  - `storm-castle-tower`: identical impure-updater hazard bookkeeping fixed, and the difficulty `<option value="medium">` corrected to `value="normal"` to match the engine's config map.

- **2 additional critical defects fixed:**
  - `realm-carver`: page now reads `sentence.term` instead of the non-existent `sentence.text`, allowing the game to start.
  - `alchemists-synthesis` and `wizard-vs-zombie`: game-frame height changed from `min(85svh, 100%)` to `"85svh"`, making the Start Game button clickable on real pointers.

- **i18n:** `en.ts` entries added for `alchemistsSynthesis`, `archersRevenge`, and `runeForgeChamber`; hardcoded Thai back buttons (`กลับไปหน้าเกม`) replaced with `t("backToGames")` in 8 sentence-game pages.

- **Layout / cosmetic:** `gryphon-patrol` world centered for 390×844; `spellweavers-run` orbs clipped to the play area; word labels widened with `wrap="none"` in `griffin-sky-joust`, `shadow-gate-dungeon`, and `village-guardian`.

- **Infrastructure / tests:** `create_room` WebSocket ack now includes `roomCode`; stale route/UI tests updated; ESLint jest/node globals added for `*.test.*` files, removing 1,858 config warnings.

- **Verification evidence:** the report documents per-game browser verification (native start click, FPS measurement, live state probe for abyssal-well), `tsc --noEmit` clean, and the full jest suite green except for the timing-sensitive `performance-benchmark.test.ts`.

## 3. Code quality observations

- Fixes are narrow and game-specific rather than broad refactors, which is appropriate for a focused bug-fix track.
- The impure-updater anti-pattern was identified and corrected consistently across three games (`haunted-library`, `abyssal-well`, `storm-castle-tower`) using a live `useRef` mirror of `gameState`. Comments in each file explain the StrictMode hazard.
- Test maintenance kept pace with code changes: stale route assertions, page i18n expectations, difficulty defaults, GameEndScreen strings, menu links, and a locale-client mock were all updated.
- Minor concern: the word-label fix uses `wrap="none"` with wider labels; the report acknowledges the edge-clipping risk on boundary-hugging entities.
- The ESLint global additions are configuration-only and do not change runtime semantics; they correctly silence false-positive `no-undef` warnings.
- A pre-existing `review-2026-07-08.md` already exists in this archive folder; this `review-2026-07-07.md` captures the same commit set with the date requested by the review process.

## 4. Risks or blockers

- `performance-benchmark.test.ts` is noted as flaky under parallel load. It passes in isolation, but this could mask real regressions in CI and should be hardened or quarantined.
- Several "playable" games still have raw i18n keys or hardcoded English headers (e.g., `paladins-twin-soul`); these were not blockers per the report but remain UX inconsistencies.
- The `babel-architect` card was set to `coming-soon` in a separate commit; the game itself is still unimplemented. If it is intended to launch, a separate implementation track is required.
- `storm-castle-tower` had a difficulty mismatch (`medium` vs `normal`) that was resolved by aligning the option to the engine's vocabulary. This is correct but worth confirming with design that "normal" is the intended player-facing label.
