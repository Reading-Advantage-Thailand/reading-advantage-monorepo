2. ข้อกำหนดทางโครงสร้างระบบ (Technical Mandates)

เกมที่ส่งเข้าประกวดจะต้องปฏิบัติตามมาตรฐานระบบของแพลตฟอร์ม (Advantage Play Kit Rules) เพื่อให้ระบบส่วนกลางสามารถทำคอมไพล์และพอร์ตขึ้นโปรดักชันได้จริง:

3.1 การจัดสรรข้อมูล (Educational I/O Interface)

  • อินพุตคำศัพท์ (Input): เกมต้องประมวลผลคำศัพท์โดยรองรับรูปแบบอาร์เรย์ของคำวัตถุตามโครงสร้างสัญญาอินเทอร์เฟซ: 
    type VocabularyItem = {
  term: string;        // คำศัพท์ หรือ ประโยคต้นทางภาษาอังกฤษ
  translation: string; // คำแปล หรือ คำตอบปลายทางภาษาไทย
}
  • เอาต์พุตและคะแนน (Output): เมื่อผู้เล่นจบเกม ระบบต้องส่งยอดคะแนนสะสมจริงผ่านฟังก์ชัน onComplete(xp) โดยคำนวณตามหลักเกณฑ์กลาง:

    XP = Math.floor(correctAnswers * accuracy)

    *หมายเหตุ: accuracy คำนวณจาก correctAnswers / totalAttempts

3.2 โครงสร้างกราฟิกเฟรมเรตสูง (Canvas-First Canvas)

  • รันบน Canvas เท่านั้น: ห้ามใช้ DOM Element หรือกล่อง HTML ธรรมดามาตกแต่งซ้อนทับบริเวณเล่นเกม (ยกเว้นคอมโพเนนต์ระดับโฮสต์) ทุกฉากและตัวละครต้องจัดการผ่านคลาสกราฟิก Phaser 4 เท่านั้น
  • ต้องมีหน้า Preload โหลดตัวเกม: เพื่อป้องกันอาการสะดุดตอนฉากกำลังรัน ทุกผลงานต้องมีกระบวนการรอโหลด assets และไฟล์เสียงประกอบทั้งหมดให้เสร็จสิ้นก่อนเริ่มเกม
  • จัดการ Memory Teardown: โค้ดคอมโพเนนต์ต้องทำความสะอาดทรัพยากรทุกครั้งเมื่อ unmount (สั่งปิด phaser instance, ดับเสียง, และยกเลิกการรออีเวนต์) เพื่อป้องกันปัญหาหน้าเว็บค้างจาก Memory Leak

3.3 รองรับขนาดสัดส่วนหน้าจอ (Responsive Viewports)

  • Compact Profile (390x844): รูปแบบแนวตั้งสำหรับสมาร์ตโฟน ปุ่มควบคุมทิศทางต้องหลบมุม ไม่บดบังปุ่มตอบคำถามหรือประโยคโจทย์ที่ผู้เรียนจำเป็นต้องอ่าน
  • Wide Profile (1440x900): รูปแบบแนวนอนสำหรับคอมพิวเตอร์ ขยายภาพพื้นหลังเพื่อใช้พื้นที่อย่างมีสไตล์และสัดส่วนคงที่ ห้ามสเกลยืดสัดส่วนหน้าจอมือถือขึ้นเดสก์ท็อปตรงๆ
  • การสลับอุปกรณ์ควบคุม: ปรับเลย์เอาต์การควบคุมอัตโนมัติ (สัมผัสผ่าน Virtual Joystick หรือ D-pad บนจอมือถือ และปุ่มคีย์บอร์ด WASD บนเดสก์ท็อป)
  • ล็อคหน้าจอไม่ให้หลุด: ใส่ CSS touch-action: none และ user-select: none บนตัวโฮสต์ เพื่อตัดปัญหาเบราว์เซอร์เผลอดึงหน้าจอลงเพื่อรีเฟรชขณะกำลังเลื่อนเล่นเกม

3.4 การพัฒนาบนระบบธีมคู่ (Dual-Theming System)

  • ตัวเกมต้องสนับสนุนการเปลี่ยนภาพสกินระหว่างสองธีมของระบบอย่างราบรื่น ได้แก่ Chibi Quest (การ์ตูนผจญภัยน่ารัก) และ Riven Lands (แฟนตาซีดาร์ก RPG) โดยห้ามไม่ให้ตัวเลขพิกัด ระยะกล่องชน (collider) หรือตำแหน่งฉากเคลื่อนที่คลาดเคลื่อนไปจากเดิม

3.5 ความง่ายและถูกต้องในการอ่านภาษาไทย (Text Legibility)

  • ตัวหนังสือประโยคไทยและคำถามต้องใช้ฟอนต์ที่ชัดเจน ไม่อัดแน่นกันเกินไปจนสระจมดินหรือซ้อนทับ และต้องไม่โดนย่อหรือถูกตัดทิ้งด้วยเครื่องหมายจุดไข่ปลา (...) กล่องข้อความควรมีพื้นหลังทึบเพื่อความชัดเจนในการอ่านข้อสอบสะกดคำ
